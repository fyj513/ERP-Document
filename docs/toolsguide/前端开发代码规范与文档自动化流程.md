# PRAM3 前端开发规范与文档自动化手册

## 第0章 前言与政策声明

### 0.1 文档目的

本文档是 PRAM3 前端团队的**开发规范与工程手册**，覆盖从需求拆解、代码编写、测试编写到文档自动生成的完整链路。

核心目标只有一个：**让代码自己说话，让文档自己生成。**

- 写代码时顺手写好 JSDoc（英文） → 自动生成 API 文档
    
- 写测试时顺手写好 `describe/it`（英文） → 自动生成测试规格说明书
    
- 提交代码前跑一遍 `npm test` → 自动验证功能正确性
    
- 合并前跑一遍 `npm run docs:all` → 自动确认文档与代码同步
    

---

### 0.2 零依赖政策（Zero-Dependency Policy）

PRAM3 交付给客户的软件产品，**不得包含任何第三方运行时依赖**。这是基于安全、可控、长期维护的考量。

#### 0.2.1 政策边界：电钻 vs 房子

用一个比喻来理解：

> 建筑公司给客户交付的是**房子**，不是**电钻**。电钻是工人施工时用的工具，房子交付后，里面不会有电钻。

表格

|类别|是否允许|说明|
|:--|:-:|:--|
|**运行时依赖（禁止）**|❌|随产品交付并在客户浏览器/服务器执行的第三方代码。如 React、Vue、lodash、axios、moment 等。|
|**构建时工具（允许）**|✅|将源代码编译/打包成产物的工具。如 PostCSS、Vite/Rollup（如果后续引入）。产物中不保留工具本身。|
|**开发测试工具（允许）**|✅|仅在开发机和 CI 流水线使用的工具。如 Jest、ESLint、JSDoc。这些工具**不进入交付产物**，客户永远看不到。|
|**外部 CDN/URL（禁止）**|❌|页面中引用 Google Fonts、外部 JS 脚本、外部 API 接口等。这是红线中的红线。|

#### 0.2.2 为什么 Jest 可以用？

Jest 属于**开发测试工具**，它的使用范围严格限定在：

1. 开发人员的本地机器
    
2. GitHub/GitLab CI 流水线
    
3. 生成测试报告和覆盖率统计
    

**Jest 的代码不会出现在最终交付的 ERP 系统中。** 客户浏览器加载的 `bundle.js` 里，只有 PRAM3 团队手写的原生 JavaScript。

#### 0.2.3 为什么 React/Vue/lodash 不能用？

这些属于**运行时依赖**：

1. 它们的代码会打包进最终产物
    
2. 它们在客户的浏览器里执行
    
3. 如果它们出现安全漏洞，PRAM3 的 ERP 系统直接暴露风险
    
4. 如果它们修改许可证（如历史上的 React 专利条款争议），PRAM3 可能面临法律风险
    

**PRAM3 的核心库（如 TimesDates）已经证明：复杂的日期时间处理完全可以自研，不需要 moment.js。**

### 0.4 术语表

表格

|术语|英文|含义|
|:--|:--|:--|
|**JSDoc**|JSDoc|JavaScript 注释标准。通过 `@param`、`@returns`、`@example` 等标签描述函数签名，可被工具提取生成 API 文档。|
|**Jest**|Jest|JavaScript 测试框架。提供 `describe`、`it`、`expect` 等 API，自动发现、执行测试并生成报告。|
|**纯门卫**|Pure Re-export|入口文件（如 `main.js`）只包含 `export { ... } from '...'`，不引入逻辑、变量、函数定义。|
|**纯函数**|Pure Function|给定相同输入，永远返回相同输出，且不产生副作用（不修改外部状态、不操作 DOM）。纯函数最容易测试。|
|**Re-export**|Re-export|从其他模块导入后立即导出，不在当前文件留存逻辑。`export { foo } from './foo.js'` 是标准写法。|
|**Describe/It**|Describe/It|Jest 的测试分组语法。`describe` 定义测试套件（按模块/场景分组），`it` 定义单个测试用例（描述期望行为）。|
|**ESLint**|ESLint|静态代码分析工具。按规则检查代码风格（如禁止 `var`、强制 JSDoc 等），在保存或提交时自动报错。|
|**CI/CD**|CI/CD|持续集成/持续部署。代码提交后自动跑测试、生成文档、检查规范，阻断不合格的合并请求。|
|**覆盖率**|Coverage|测试代码覆盖了多少业务代码的指标。Jest 可生成 HTML 报告，显示哪些行被测过、哪些没测过。|
|**Mock**|Mock|测试中伪造外部依赖（如后端 API、浏览器 API），让测试只关注当前模块逻辑，不真的发网络请求。|
|**零依赖**|Zero-Dependency|PRAM3 交付产物不携带任何第三方库代码，所有功能自研或基于浏览器原生 API。|

### 1.2 `src/main.js` 规范：唯一入口文件

`src/main.js` 是每个库的**门面**，外部使用者通过它访问库的全部能力。

#### 必须遵守的三条铁律

**铁律一：有且仅有 `main.js` 一个入口**

JSON

复制

```json
// package.json
{
  "main": "src/main.js"
}
```

- 禁止创建 `src/index.js`
    
- 禁止在 `src/` 根目录放其他"看起来像入口"的文件
    

**铁律二：`main.js` 只做两件事**

1. **Re-export（门卫）**：把子模块的公共 API 统一暴露
    
2. **工厂函数**：提供便捷的顶层入口（如 `toDateTimeObj()`）
    

JavaScript

复制

```javascript
// src/main.js -- TimesDates Example

/**
 * PRAM3 Time & Date Core Library
 *
 * Works in both browser (client) and server (BUN/Node) environments.
 *
 * Quick-start:
 * ```javascript
 * import { initDateTimeConfig, toDateTimeObj, toTimeObj } from '@pram3/datetime';
 *
 * initDateTimeConfig({
 *   company: { timezone: 'Asia/Shanghai', locale: 'zh-CN' }
 * });
 *
 * const meeting = toDateTimeObj('2024-01-20 15:00:00');
 * console.log(meeting?.localDateTime);  // "2024-01-20 15:00:00"
 * ```
 *
 * @module TimesDates
 */

// ===== 1. Re-export (gatekeeper) =====
export { DateTimeObj, RelativeTime } from './DateTimeObj.js';
export { TimeObj } from './TimeObj.js';
export {
  DateTimeConfigManager,
  getConfig,
  initDateTimeConfig,
} from './DateTimeConfigManager.js';
export { formatDateTime } from './formatter.js';
export { parseDateTime, parseTimeOnly, formatTimeOnly } from './parser.js';

// ===== 2. Factory functions =====
import { DateTimeObj } from './DateTimeObj.js';
import { TimeObj } from './TimeObj.js';

/**
 * Parse a string into a DateTimeObj.
 * @param {string} value - Date/time string
 * @param {string} [format='Sensible default'] - Format string
 * @returns {DateTimeObj|null}
 */
export function toDateTimeObj(value, format = 'Sensible default') {
  return DateTimeObj.fromString(value, format);
}

/**
 * Parse a time string into a TimeObj.
 * @param {string} value - Time string
 * @param {boolean} [sameTimeGlobally=false] - Whether timezone adjustment applies
 * @returns {TimeObj|null}
 */
export function toTimeObj(value, sameTimeGlobally = false) {
  return TimeObj.fromString(value, sameTimeGlobally);
}
```

**铁律三：`main.js` 禁止写具体实现**

❌ 禁止在 `main.js` 里出现：

- 算法逻辑（如 `format.replace(/%.../)`）
    
- 工具函数（如 `padZero()`）
    
- `console.log` / `console.warn`（调试残留）
    
- 变量声明（`const` / `let` / `var`）—— 工厂函数参数除外
    

✅ 只允许出现：

- `export { ... } from '...'`
    
- `import`（仅用于工厂函数）
    
- `export function`（仅工厂函数，且函数体内只有一行 `return` 或简单调用）

### 1.3 JSDoc 注释规范

JSDoc 是 PRAM3 前端文档自动化的**唯一数据源**。API 文档从 JSDoc 生成，示例代码从 JSDoc 提取验证。注释质量直接决定文档质量。

> ⚠️ **核心原则**：只有**需求文档中明确提到的 API** 才需要写完整 JSDoc。需求未提及的内部方法，标记 `@private` 即可。

#### 1.3.1 强制要求：谁必须写 JSDoc？

表格

|文件类型|必须写 JSDoc 的对象|说明|
|:--|:--|:--|
|`src/main.js`|所有 `export function`（工厂函数）|外部用户直接调用的入口，需求文档中提到的才写|
|`src/*Obj.js`|需求文档中提到的 **public 类和方法**|类的文档从 JSDoc 提取|
|`src/constants.js`|所有 `export const`|至少一行英文描述|

**以下情况不写完整 JSDoc**：

表格

|文件/对象|处理方式|说明|
|:--|:--|:--|
|内部函数（未 export）|单行注释 `/** Description */` 即可|不进入 API 文档|
|需求未提及的类方法|加 `@private` 标签|JSDoc 生成文档时自动跳过|
|`src/formatter.js`、`src/parser.js` 等内部工具|不写 JSDoc（除非需求文档要求暴露）|不进入 API 文档|

**示例：需求未提及的方法标记 `@private`**

JavaScript

复制

   * @private
   */

  /**
   * Check if this date is before another.
   * @private
   */
  isBefore(other) { ... }

```

#### 1.3.4 `@example` 铁律

`@example` 里的代码**必须是真实可复制的**，原因：

1. **API 文档**会原样展示它，用户直接复制粘贴就能跑
    
2. **未来可接 doctest** 自动验证示例是否过时（代码改了，示例没改 → 测试失败 → 倒逼同步）
    

**必须遵守的规则**：

表格

|规则|说明|
|:--|:--|
|代码必须缩进|相对于 `*` 至少 4 个空格|
|最后一行用 `// =>` 标注预期输出|`// => '2024-01-15'`|
|变量声明后必须再输出变量名|`const x = foo(); x; // => 1`（doctest 需要）|
|禁止写伪代码|❌ `// 这里返回日期`|
|禁止写省略号|❌ `formatDateTime(date, ...)`|

**正确示例**：

JavaScript

复制

```javascript
 * @example
 * const d = new Date(2024, 0, 15, 14, 30, 0);
 * formatDateTime(d, '%Y-%m-%d', { timezone: 'UTC' });
 * // => '2024-01-15'
```

**错误示例**：

JavaScript

复制

```javascript
 * @example
 * // Format the date
 * formatDateTime(date, format, config);
 * // Returns a string
```

#### 1.4.2 工具函数文件（`src/formatter.js`、`src/parser.js` 等）

工具函数是**最容易测试、最容易文档化**的代码单元。ERP 前端的大量逻辑（日期计算、数据格式化、校验）都应拆成纯函数，放到独立文件。

**文件拆分原则**：

表格

|场景|做法|
|:--|:--|
|单一职责|一个文件只做一件事。`formatter.js` 只格式化，`parser.js` 只解析。|
|纯函数优先|给定相同输入，永远返回相同输出，不操作 DOM、不发请求、不改全局状态。|
|可测试性|每个导出函数都能在 Node.js 环境里独立测试，不需要浏览器环境。|

**关于 JSDoc**：工具函数文件中的函数**如果需求文档要求暴露**，需要写完整 JSDoc；如果仅作为内部实现使用，单行英文注释即可。JSDoc 生成 API 文档时只扫描需求中指定的文件（通过 `jsdoc.json` 的 `include` 配置控制）。

**工具函数编写铁律**：

表格

|规则|说明|
|:--|:--|
|先校验|参数类型不对立刻抛 `TypeError`，不要静默失败|
|早返回|每个分支用 `if (...) return` 处理，减少嵌套|
|纯计算|不读 `localStorage`、不写 `document`、不发 `fetch`|
|原子性|一个函数只做一件事，`parseTimeOnly` 不顺便格式化|
|可预测|`null` 表示解析失败，不要有时返回 `undefined`|

### 2.2 `describe` / `it` 分组与命名规范

#### 2.2.1 分组结构（三层）

plain

复制

```plain

**示例**：

复制

```javascript

      expect(now).not.toBeNull();
      expect(now.timestamp).toBeGreaterThan(0);

表格

|层级|规范|正确示例|错误示例|
|:--|:--|:--|:--|
|`describe`|写**被测对象名**或**场景名**|`'DateTimeObj'`、`'Formatting'`|`'test1'`、`'dt测试'`|

**禁止的写法**：

JavaScript

复制

```javascript
// ❌ describe with meaningless name

```

## 第5章 存量项目迁移原则

PRAM3_CORELIBS 下已有多个历史项目（`binaryUtils`、`classAsync`、`compressor`、`coreLib`、`keyDerivation` 等），未遵循本规范。本章提供**渐进式迁移策略**。

### 5.1 迁移优先级

表格

|优先级|目标|原因|
|:-:|:--|:--|
|**P0**|入口文件统一为 `main.js`，删除/合并 `index.js`|外部用户最先接触，影响最大|
|**P1**|为需求文档中提到的 API 补全英文 JSDoc（`@param`、`@returns`、`@example`）|文档自动化的前提|
|**P2**|为需求中提到的 API 编写 `api.test.js`（英文 describe/it）|保障功能不被后续重构破坏|
|**P3**|补充内部单元测试 `unit.test.js`|细化边界和异常覆盖|
|**P4**|非需求 API 标记 `@private`|防止 API 文档泄露内部接口|
|**P5**|接入 ESLint + Prettier|统一代码风格|
|**P6**|接入 `npm run docs:all`|完整文档自动化闭环|

### 5.2 渐进式补充策略

#### 5.2.1 入口文件改造（每个库 30 分钟）

1. 检查现有入口：是 `index.js`？`main.js`？还是两者都有？
    
2. 合并到 `main.js`，删除 `index.js`
    
3. 改造 `main.js` 为**纯门卫 + 工厂函数**格式
    
4. 更新 `package.json` 的 `"main"` 字段
    

#### 5.2.2 JSDoc 补充策略

**只补需求文档中提到的 API**，内部方法标记 `@private`。

检查清单：

- [ ] 需求中提到的类上方有 `/** Class description */`（英文）
    
- [ ] 构造函数有 `@param`
    
- [ ] 需求中提到的每个 public 方法有 `@param`、`@returns`、`@example`（英文）
    
- [ ] 需求未提及的方法已标记 `@private`
    
- [ ] Getter 属性有 `@returns` 和 `@example`（英文）
    

#### 5.2.3 测试补充策略

**先写 `api.test.js`**（覆盖需求接口，英文描述），**再写 `unit.test.js`**（覆盖边界，英文描述）。

### 6.6 `scripts/gen-test-doc.js`

**作用**：从 `tests/api.test.js` 和 `tests/unit.test.js` 提取测试结构，自动生成**英文**测试规格说明书。

**注意**：

- 输出路径为 `docs/TEST_API_AUTO.md`
    
- 所有标题、描述、字段名**均为英文**
    
- 测试代码中的 `describe/it` 也必须是英文，否则生成的文档会包含非英文内容
    

JavaScript

复制

```javascript
import fs from 'fs';
import path from 'path';
import { fileURLToPath } from 'url';

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

// ========== State Machine Parser ==========

function parseTestFile(content) {
  const lines = content.split('\n');
  const root = { name: 'Root', children: [], its: [] };
  const stack = [root];

  let mode = 'normal';
  let currentIt = null;
  let itBraceCount = 0;
  let itLines = [];

  for (const line of lines) {
    const trimmed = line.trim();

    const descMatch = trimmed.match(/describe\(['"`](.+?)['"`],\s*\(\)\s*=>\s*\{/);
    if (descMatch && mode === 'normal') {
      const newNode = { name: descMatch[1], children: [], its: [] };
      stack[stack.length - 1].children.push(newNode);
      stack.push(newNode);
      continue;
    }

    const itMatch = trimmed.match(/it\(['"`](.+?)['"`],\s*\(\)\s*=>\s*\{/);
    if (itMatch && mode === 'normal') {
      mode = 'in-it';
      currentIt = { title: itMatch[1], body: [] };
      const opens = (line.match(/\{/g) || []).length;
      const closes = (line.match(/\}/g) || []).length;
      itBraceCount = opens - closes;
      continue;
    }

    if (mode === 'in-it') {
      const opens = (line.match(/\{/g) || []).length;
      const closes = (line.match(/\}/g) || []).length;
      itBraceCount += opens - closes;

      if (itBraceCount === 0 && trimmed.endsWith(');')) {
        currentIt.body = itLines.join('\n');
        stack[stack.length - 1].its.push(currentIt);
        mode = 'normal';
        currentIt = null;
        itLines = [];
      } else {
        itLines.push(line);
      }
      continue;
    }

    if (trimmed === '});' && stack.length > 1 && mode === 'normal') {
      stack.pop();
    }
  }

  return root;
}

function extractInputs(body) {
  const inputs = [];
  const lines = body.split('\n');
  for (const line of lines) {
    const t = line.trim();
    if (t.startsWith('const ') && t.includes('=')) {
      inputs.push(t.replace(/;$/, ''));
    }
  }
  return inputs;
}

function extractSteps(body) {
  const steps = [];
  const lines = body.split('\n');
  for (const line of lines) {
    const t = line.trim();
    if (!t || t.startsWith('//') || t.startsWith('const ') || t.startsWith('expect(')) continue;
    if (t.startsWith('DateTimeConfigManager.resetInstance') || t.startsWith('initDateTimeConfig')) continue;
    steps.push(t.replace(/;$/, ''));
  }
  return steps;
}

function extractExpectations(body) {
  const expects = [];
  const regex = /expect\(([\s\S]*?)\)\.(\w+)\(([\s\S]*?)\)(?:\.(\w+)\(([\s\S]*?)\))?/g;
  let m;
  while ((m = regex.exec(body)) !== null) {
    const [, actual, m1, e1, m2, e2] = m;
    expects.push({
      actual: actual.replace(/\s+/g, ' ').trim(),
      method1: m1,
      expected1: e1 ? e1.replace(/\s+/g, ' ').trim() : '',
      method2: m2,
      expected2: e2 ? e2.replace(/\s+/g, ' ').trim() : '',
    });
  }
  return expects;
}

function formatExpectation(exp) {
  const { actual, method1, expected1, method2, expected2 } = exp;
  if (method1 === 'toBe' || method1 === 'toEqual') {
    return `- \`${actual}\` should equal \`${expected1}\``;
  }
  if (method1 === 'toBeNull') return `- \`${actual}\` should return null`;
  if (method1 === 'not' && method2 === 'toBeNull') return `- \`${actual}\` should not return null`;
  if (method1 === 'toBeGreaterThan') return `- \`${actual}\` should be greater than \`${expected1}\``;
  if (method1 === 'toThrow') return `- \`${actual}\` should throw \`${expected1}\``;
  if (method1 === 'toBe' && expected1 === 'true') return `- \`${actual}\` should return true`;
  if (method1 === 'toBe' && expected1 === 'false') return `- \`${actual}\` should return false`;
  if (method1 === 'not' && method2 === 'toBe') return `- \`${actual}\` should not equal \`${expected2}\``;
  return `- \`${actual}\` -> ${method1}(${expected1})`;
}

let tcNumber = 1;

function renderNode(node, level = 2) {
  let md = '';
  for (const it of node.its) {
    const inputs = extractInputs(it.body);
    const steps = extractSteps(it.body);
    const expects = extractExpectations(it.body);

    md += `${'#'.repeat(level)} TC-${String(tcNumber).padStart(3, '0')}: ${it.title}\n\n`;

    if (inputs.length) {
      md += `**Test Data / Input:**\n`;
      for (const inp of inputs) md += `- \`${inp}\`\n`;
      md += `\n`;
    }

    if (steps.length) {
      md += `**Steps:**\n`;
      for (const step of steps) md += `1. \`${step}\`\n`;
      md += `\n`;
    }

    if (expects.length) {
      md += `**Expected Results:**\n`;
      for (const exp of expects) md += `${formatExpectation(exp)}\n`;
      md += `\n`;
    }

    md += `<details>\n<summary>Original Test Code</summary>\n\n\`\`\`javascript\n${it.body.trim()}\n\`\`\`\n\n</details>\n\n---\n\n`;
    tcNumber++;
  }

  for (const child of node.children) {
    md += `${'#'.repeat(level)} ${child.name}\n\n`;
    md += renderNode(child, level + 1);
  }

  return md;
}

// ========== Main Entry: Support Multiple Test Files ==========

const testFiles = [
  { path: path.join(__dirname, '../tests/api.test.js'), label: 'Public API Tests' },
  { path: path.join(__dirname, '../tests/unit.test.js'), label: 'Internal Unit Tests' },
];

let totalIts = 0;
let md = `# TimesDates Test Specification\n\n`;
md += `> **Generated from**: \`tests/api.test.js\`, \`tests/unit.test.js\`  \n`;
md += `> **Generated at**: ${new Date().toISOString()}  \n`;
md += `> **Note**: This document is auto-generated from test code. Do not edit manually.  \n\n`;
md += `---\n\n`;

for (const fileInfo of testFiles) {
  if (!fs.existsSync(fileInfo.path)) {
    console.warn(`Warning: file not found, skipping: ${fileInfo.path}`);
    continue;
  }

  const content = fs.readFileSync(fileInfo.path, 'utf8');
  const tree = parseTestFile(content);

  function countIts(node) {
    totalIts += node.its.length;
    for (const c of node.children) countIts(c);
  }
  countIts(tree);

  md += `## ${fileInfo.label}\n\n`;

  for (const module of tree.children) {
    md += `### ${module.name}\n\n`;
    md += renderNode(module, 4);
  }
}

const outPath = path.join(__dirname, '../docs/TEST_API_AUTO.md');
fs.writeFileSync(outPath, md);
console.log(`Test specification generated: ${outPath}`);
console.log(`Total test cases: ${totalIts}`);

## 附录 A：JSDoc 覆盖范围判定速查

### 谁需要完整 JSDoc（英文）？

表格

|对象|JSDoc 要求|原因|
|:--|:--|:--|
|需求文档中提到的 `export function`（工厂函数）|✅ 完整 JSDoc（`@param`、`@returns`、`@example`）|出现在 API 文档中|
|需求文档中提到的类 `public` 方法|✅ 完整 JSDoc|出现在 API 文档中|
|需求文档中提到的类 `getter` 属性|✅ 完整 JSDoc（至少 `@returns`、`@example`）|出现在 API 文档中|
|`export const` 常量|✅ 简单 JSDoc（`@constant`、`@type` + 英文描述）|出现在 API 文档中|
|需求未提及的类方法|❌ 不需要完整 JSDoc，标记 `@private` 即可|不出现在 API 文档中|
|内部函数（未 export）|❌ 单行英文注释 `/** Description */` 即可|不出现在 API 文档中|
|内部工具函数（formatter.js 等）|❌ 不需要 JSDoc（除非需求文档要求暴露）|不出现在 API 文档中|

### 判定流程

plain

复制

```plain
这个函数/方法是否在需求文档中？
  ├── 是 → 写完整英文 JSDoc（@param, @returns, @example）
  │         → 确保 jsdoc.json 的 include 包含该文件
  │
  └── 否 → 是否 export？
            ├── 是（类内部方法但需求未提）→ 加 @private
            │                              → 简单英文注释即可
            │
            └── 否（内部辅助函数）        → 单行英文注释即可
                                          → 不进入任何文档
```

## 附录 B：需求变更时的操作清单

当需求文档变更（新增/移除 API）时，按以下清单同步：

- [ ] 更新 `jsdoc.json` 的 `include`（新增文件加入 / 移除文件删除）
    
- [ ] 新增 API：写完整英文 JSDoc（`@param`、`@returns`、`@example`）
    
- [ ] 新增 API：在 `api.test.js` 中补充测试用例（英文 describe/it）
    
- [ ] 移除 API：将对应方法标记 `@private` 或删除
    
- [ ] 移除 API：移除对应的测试用例
    
- [ ] 运行 `npm run docs:all` 确认 API 文档内容正确
    
- [ ] 对照需求文档核对 API 文档中的条目，确保一一对应
