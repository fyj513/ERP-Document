# PRAM3 前端开发规范手册

## 核心规则

**零依赖政策**：交付产物不得包含任何第三方运行时库（React、lodash、axios 等）。ESLint、Prettier 等开发工具仅在开发和 CI 阶段使用，不进入交付产物。

**语言规范**：代码中所有注释和测试描述必须用**英文**。中文出现在注释或测试描述中，Code Review 直接驳回。

## 第2章 `src/main.js` 规范

`main.js` 只做两件事：**Re-export（门卫）** 和 **`@module` 注释**。禁止写任何算法逻辑。

```javascript
// AI-generated: module entry point for SortsFilters library

/**
 * SortsFilters — Generic sorting and filtering functions.
 *
 * @module SortsFilters
 */

import { DefaultFilter } from './filters.js';
import { DefaultSort }   from './sorts.js';

export { DefaultFilter, DefaultSort };
```

**禁止在 `main.js` 出现**：算法逻辑、工具函数、`console.log`、变量声明、手动命名空间对象（如 `export const Libs = { ... }`）。

> **为什么不手动包命名空间？** 命名空间由构建系统根据 `lib.json` 的 `path` 字段自动挂载。手动包一层会导致重复嵌套。详见下方第2.1章。

---

## 第2.1章 `lib.json` 命名空间规范

构建系统读取 `lib.json` 的 `path` 字段，把 `main.js` 的每个具名导出自动挂到对应路径下。

```json
{
    "path": "Libs.Utils.SortsFilters"
}
```

`main.js` 导出 `DefaultFilter` 和 `DefaultSort` 后，构建系统自动生成：

```
Libs.Utils.SortsFilters.DefaultFilter
Libs.Utils.SortsFilters.DefaultSort
```

**铁律**：`main.js` 只管导出函数/类本身，命名空间路径只在 `lib.json` 里填，两者职责分离。

## 第2.2章 导出类继承规范

所有对外导出的 API 类必须继承 `CoreLib`。

```javascript
// AI-generated: inherit CoreLib to comply with library base class requirement
import { CoreLib } from '../../coreLib/src/main.js';

export class MyClass extends CoreLib {
    // ...
}
```

继承链：

```
ClassAsync          ← 提供 .Ready（Promise）和 .IsReady（boolean）异步初始化能力
    └── CoreLib     ← 所有库的统一基类（当前为 stub，为未来扩展预留钩子）
            └── 各库导出类
```

> **为什么要继承 CoreLib 而不是直接写 class？** CoreLib 是未来给所有库统一加功能的扩展点。现在继承它是空操作，但一旦 CoreLib 新增能力，所有库自动获得，无需逐一修改。

## 第3章 源码注释规范

> **注释是数据，脚本是解析器。** 注释写得规范，`script/api.js` 才能正确生成文档。

### 脚本识别规则

`script/api.js` 只看注释本身，不关心后面跟的是 `export function`、类方法、getter 还是其他写法：

| 注释特征 | 脚本行为 |
|---|---|
| 有 `@example`，没有 `@private` | ✅ 识别为公开 API，生成文档 |
| 有 `@private` | ❌ 跳过 |
| 没有 `@example` | ❌ 跳过 |

### 注释结构

公开 API 注释由 **5 个命名区块 + 1 个标签**组成，必须按顺序书写：

```javascript
/**
 * One sentence describing what the function does.    ← ① 描述（第一行非空行）
 *
 * Inputs:                                            ← ② 输入区块
 * - name  {Type}          Description. Allowed values.
 * - name  {Type=default}  Description. Has a default value.
 *
 * Outputs:                                           ← ③ 输出区块
 * - {ReturnType}  Description of the return value.
 *
 * Throws:                                            ← ④ 异常区块
 * - TypeError  When this condition occurs.
 * - (none)     No exceptions thrown.    ← 不抛异常时写 (none)，文档自动隐藏此表格
 *
 * Rules:                                             ← ⑤ 行为规则区块
 * 1. condition or edge case → how it is handled
 * 2. condition or edge case → how it is handled
 *
 * @example                                           ← ⑥ 示例标签（必须有，否则脚本跳过）
 * // Group label comment
 * FunctionName(arg1, arg2)   // => returnValue
 */
```

### 各区块格式规则

**② `Inputs:` 区块** — 每行一个参数，格式：`- name  {Type}  Description`

| 字段 | 格式 | 示例 |
|---|---|---|
| 参数名 | `\w+`，不加括号 | `data`、`reverse`、`sortBy` |
| 类型（无默认值） | `{Type}` | `{Array}`、`{string\|null}` |
| 类型（有默认值） | `{Type=default}` | `{boolean=false}`、`{null\|string=null}` |
| 联合类型 | `\|` 分隔 | `{null\|string\|number[]=null}` |
| 描述 | 自由文本，**单行** | `Array to sort. Any element types.` |

**③ `Outputs:` 区块** — 格式：`- {Type}  Description`

**④ `Throws:` 区块** — 格式：`- ErrorType  Condition description`

- 不抛异常时写 `- (none)  ...`，生成文档时自动跳过 Throws 表格

**⑤ `Rules:` 区块** — 格式：`N. Condition → Behavior`

- `→` **两侧必须各有一个空格**（脚本以带空格的 `→` 作为分隔符）
- Behavior 列内部的 `→`（紧贴文字，无空格）不影响解析，可自由使用

### 注释 → 文档对应关系

```javascript
/**
 * Sorts an array and returns a new sorted copy.      ← ① 函数描述行
 *
 * Inputs:
 * - data     {Array}            Array to sort.       ← ② name / type / desc → Parameters 表格行
 * - reverse  {boolean=false}    true = descending.   ← ② type=default → Default 列显示 `false`
 *
 * Outputs:
 * - {Array}  New sorted copy.                        ← ③ type / desc → Returns 行
 *
 * Throws:
 * - TypeError  data is not an Array.                 ← ④ errorType / condition → Throws 表格行
 *
 * Rules:
 * 1. null in array → always sorted to end            ← ⑤ condition → behavior → Rules 表格行
 *
 * @example
 * DefaultSort([3, 1, 2])   // => [1, 2, 3]           ← ⑥ 原样输出到 Examples 代码块
 */
export function DefaultSort(data, reverse = false) { ... }
↑_________________________________________________________↑
函数签名由脚本从代码行自动提取，不需要手动写在注释里
```

生成的文档片段：

```markdown
### `DefaultSort(data, reverse = false)`              ← 签名自动从代码提取

Sorts an array and returns a new sorted copy.         ← ①

**Parameters**
| Name      | Type      | Default      | Description      |
|-----------|-----------|--------------|------------------|
| `data`    | `Array`   | *(required)* | Array to sort.   |  ← ②
| `reverse` | `boolean` | `false`      | true=descending. |  ← ②

**Returns**: `Array` — New sorted copy.               ← ③

**Throws**
| Error       | Condition               |
|-------------|-------------------------|
| `TypeError` | data is not an Array.   |  ← ④

**Rules**
| # | Condition     | Behavior             |
|---|---------------|----------------------|
| 1 | null in array | always sorted to end |  ← ⑤

**Examples**
DefaultSort([3, 1, 2])   // => [1, 2, 3]              ← ⑥
```

### 完整示例

```javascript
// AI-generated: DefaultSort implementation for the SortsFilters library.
/**
 * Sorts an array and returns a new sorted copy without mutating the original.
 *
 * Inputs:
 * - data     {Array}                                     Array to sort. Any element types.
 * - reverse  {boolean=false}                             true = descending order.
 * - sortBy   {null|string|number|string[]|number[]=null} Key selector: null=sort by value; string=object key; number=array/JSONB index; string[]/number[]=multi-key priority list.
 *
 * Outputs:
 * - {Array}  New sorted array. Original is never mutated.
 *
 * Throws:
 * - TypeError  data is not an Array.
 * - TypeError  reverse is not a boolean.
 * - TypeError  sortBy is invalid: negative index, float, mixed-type array, or unsupported type.
 *
 * Rules:
 * 1. null / undefined in array → always pinned to end, ignores reverse
 * 2. missing object key or out-of-bounds index → treated as null
 * 3. mixed-type priority → number+string → boolean → array → object → null → undefined
 * 4. sortBy="" or sortBy=[] → silently normalized to null
 *
 * @example
 * // Numbers and strings (natural sort)
 * DefaultSort([3, 1, 2])                             // => [1, 2, 3]
 * DefaultSort([3, 1, 2], true)                       // => [3, 2, 1]
 *
 * // sortBy: single object key
 * DefaultSort([{n:'Bob'},{n:'Alice'}], false, 'n')   // => [{n:'Alice'},{n:'Bob'}]
 */
export function DefaultSort(data, reverse = false, sortBy = null) { ... }
```

### 注释规则速查

| 规则 | 说明 |
|---|---|
| 公开函数 | 必须写全 5 个区块（Inputs / Outputs / Throws / Rules）+ `@example` |
| 内部函数 | 只需加 `@private`，脚本自动跳过 |
| 参数有默认值 | 在类型里写 `{Type=default}`，如 `{boolean=false}` |
| 函数不抛错误 | Throws: 写 `- (none)  ...`，文档中不生成 Throws 表格 |
| Rules 分隔符 | `→` 两侧各一个空格；Behavior 内部的 `→` 无需空格 |
| 描述行 | 只写一行；第一个非空、非区块标题行即为描述 |
| `@example` 分组 | `//` 注释行作为分组标题；`// =>` 后是具体返回值 |
| 无 `@example` | 脚本跳过，不生成文档 |
| 有 `@private` | 脚本跳过，不生成文档 |

## 第4章 测试文件规范

### 两个测试文件的职责划分

测试必须拆成两个文件，分别对应不同的视角：

| 文件 | 命名规则 | 测试内容 | 视角 |
|---|---|---|---|
| `main.test.js` | **固定名，不可更改** | 需求里列出的公开 API | 用户视角——对外行为 |
| `<libname>.test.js` | **以库名命名**，如 `sorts.test.js` | 标了 `@private` 的内部方法 | 开发者视角——实现细节 |

**为什么要拆？** 公开 API 测试关注"结果"，内部测试关注"实现"。内部重构时只要对外行为不变，`main.test.js` 就不应该报错；而内部测试文件允许跟着实现一起改。

生成测试文档时两个文件会分开扫描，脚本根据文件名自动打标签——`main.test.js` 标为 **Public API Tests**，其他文件标为 **Internal Unit Tests**：

```bash
bun script/test.js \
    --files tests/main.test.js,tests/sorts.test.js,tests/filters.test.js \
    --out docs/TEST_AUTO.md \
    --title "SortsFilters Test Specification"
```

## 第4.1章 测试注释规范

> 注释是数据，脚本是解析器。注释写得规范，`script/test.js` 才能正确生成测试文档。

### 注释与文档的一一对应关系

```javascript
/**
 * Verify that mmh2 returns a bigint.   ← ① 分组标题 + Description 列
 *    ↑
 *    └─ "Verify that mmh2" 中的 mmh2 → 生成 ### `mmh2` 分组标题
 *       整句话                        → 生成表格 Description 列
 *
 * @param {string} data - Murmur.mmh2('test')
 *                         ↑
 *                         └─ ② Input 列
 *
 * @returns {boolean} typeof result === 'bigint' — Happy Path
 *                    ↑                             ↑
 *                    └─ ③ Output 列                └─ ④ Scenario 列
 *
 * @reason One sentence explaining why this is the expected result.  ← ⑤ Reason 列（Edge/Error 必填）
 */
```

生成的表格一行：

| # | Description | Input | Output | Scenario | Reason |
|---|---|---|---|---|---|
| TC-001 | Verify that mmh2 returns a bigint. | `Murmur.mmh2('test')` | `typeof result === 'bigint'` | Happy Path | |

### 脚本识别规则

`script/test.js` 只看注释本身，不关心后面跟的是具名函数、箭头函数还是其他任何写法：

| 注释特征 | 脚本行为 |
|---|---|
| 描述以 `Verify that 函数名` 开头 | ✅ 识别为测试用例，生成文档 |
| 描述不以 `Verify that` 开头 | ❌ 跳过 |
| 有 `@reason` | ✅ 写入 Reason 列 |
| 无 `@reason` | Reason 列留空（Happy Path 默认省略） |

### 标准模板

```javascript
/**
 * Verify that 函数名 具体在测什么。（只写一行，不换行续写）  ← ① 必须以 "Verify that 函数名" 开头
 *
 * @param {类型} data - 调用代码            ← ② Input 列
 * @returns {类型} 期望结果 — 场景类型      ← ③ Output 列 — ④ Scenario 列
 * @reason 一句话说明为什么是这个结果（Edge / Error Case 必填）← ⑤ Reason 列
 */
// 后面跟什么代码写法都可以，脚本只认注释
runTest('描述', () => { ... });
```

### 关键规则

**① 描述第一行必须以 `Verify that 函数名` 开头，且只写一行** — 脚本用函数名分组；多行会被空格拼接后全部塞入 Description 列：

```javascript
// ✅ 正确
/**
 * Verify that mmh2 returns a bigint.
 */

// ❌ 错误 — 脚本无法识别函数名，无法分组
/**
 * mmh2 should return a bigint.
 */

// ❌ 错误 — 第二行会被拼入 Description，导致列内容过长
/**
 * Verify that mmh2 returns a bigint.
 * This is tested because bigint is required for 64-bit output.
 */
```

**④ `@returns` 末尾用 `—` 分隔场景类型**（只能写这三个）：

```javascript
@returns {boolean} typeof result === 'bigint' — Happy Path

@returns {boolean} both return equal values — Edge Case

@returns {Error} throws an Error — Error Case
```

**⑤ `@reason` 使用规则**：

| 场景类型 | `@reason` | 说明 |
|---|---|---|
| Happy Path | 省略 | 正常行为无需解释，Reason 列留空 |
| Edge Case | **必填** | 说明边界条件下为何产生这个结果 |
| Error Case | **必填** | 说明触发 TypeError 的具体校验条件 |

```javascript
// ✅ Edge Case — 必须写 @reason
/**
 * Verify that DefaultSort keeps null before undefined when both present.
 * @param {Array} data - DefaultSort([null, undefined, null])
 * @returns {boolean} result equals [null, null, undefined] — Edge Case
 * @reason _T.NULL=4 and _T.UNDEF=5; null's group constant is lower so it sorts before undefined.
 */

// ✅ Happy Path — @reason 省略
/**
 * Verify that DefaultSort sorts a number array ascending.
 * @param {Array} data - DefaultSort([5, 3, 8, 1])
 * @returns {boolean} result equals [1, 3, 5, 8] — Happy Path
 */
```

## 第5章 文档自动化

### 工作原理

脚本不依赖任何第三方工具，直接读文件、用正则扫注释、输出 Markdown：

```
源码注释 → script/api.js（正则解析）→ docs/API_AUTO.md
测试注释 → script/test.js（正则解析）→ docs/TEST_AUTO.md
```

### 常用命令

从 `Source/sortsFilters/` 目录下执行：

| 命令 | 作用 |
|---|---|
| `bun script/api.js --files "src/sorts.js:DefaultSort,src/filters.js:DefaultFilter" --out docs/API_AUTO.md --title "SortsFilters API Reference"` | 生成 API 文档 |
| `bun script/test.js --files "tests/main.test.js,tests/sorts.test.js,tests/filters.test.js" --out docs/TEST_AUTO.md --title "SortsFilters Test Specification"` | 生成测试文档 |

### 什么时候需要改脚本

脚本是纯注释驱动的，**绝大多数情况下不需要改脚本**：

| 情况 | 做什么 |
|---|---|
| 新增公开函数/方法 | 只需按规范写注释（有 `@example`，无 `@private`），脚本自动扫到 |
| 新增测试 | 只需注释以 `Verify that 函数名` 开头，脚本自动扫到 |
| 新增源码文件或测试文件 | 在运行命令的 `--files` 参数里追加新文件路径即可 |
