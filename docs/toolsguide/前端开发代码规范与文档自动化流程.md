# PRAM3 前端开发规范手册
## 核心规则
**零依赖政策**：交付产物不得包含任何第三方运行时库（React、lodash、axios 等）。Jest、ESLint、jsdoc 等开发工具仅在开发和 CI 阶段使用，不进入交付产物。

**语言规范**：代码中所有 JSDoc 注释和测试描述（`describe` / `it`）必须用**英文**。中文出现在 JSDoc 或测试描述中，Code Review 直接驳回。

## 第1章 目录结构

每个库必须遵循以下结构：

```

HashFunctions/

├── docs/

│   ├── api-html/          ← jsdoc 生成，禁止手动修改

│   ├── TEST_API_AUTO.md   ← gen-test-doc.js 生成，禁止手动修改

│   └── index.md            ← build工具自动生成

├── scripts/

│   └── gen-test-doc.js    ← 测试文档生成脚本

├── src/

│   ├── main.js            ← 唯一入口文件

│   ├── murmur.js          ← 功能模块

│   ├── sha.js             ← 功能模块

│   └── utils.js           ← 内部工具（不暴露给外部）

├── tests/

│   ├── main.test.js       ← 公开 API 测试

│   └── unit.test.js       ← 内部单元测试

├── .babelrc

├── jsdoc.json

└── package.json

```
 
**铁律**：

- `src/main.js` 是唯一入口，**禁止创建 `src/index.js`**

- 每个 `src/*.js` 文件不超过 300 行

- `docs/api-html/` 和 `docs/TEST_API_AUTO.md` 由工具自动生成，禁止手动修改

## 第2章 `src/main.js` 规范

  

`main.js` 只做两件事：**Re-export（门卫）** 和 **`@module` 注释**。禁止写任何算法逻辑。

  

```javascript

// AI-generated: module entry point for HashFunctions library

  

/**

 * HashFunctions — Non-cryptographic (Murmur) and cryptographic (SHA) hash functions.

 *

 * All functions accept: string, any TypedArray (e.g. Uint8Array), or ArrayBuffer.

 *

 * @module HashFunctions

 */

  

// ===== Re-exports (gatekeeper) =====

  

import * as Murmur from './murmur.js';

import * as SHA from './sha.js';

  

/**

 * Namespace object matching the library path Libs.Crypto.Hash.

 * @type {{ Crypto: { Hash: { Murmur: object, SHA: object } } }}

 */

export const Libs = {

    Crypto: {

        Hash: { Murmur, SHA }

    }

};

  

export { Murmur, SHA };

```

  

**禁止在 `main.js` 出现**：算法逻辑、工具函数、`console.log`、变量声明。

## 第3章 JSDoc 注释规范

**只有需求文档中提到的公开 API 才需要写完整 JSDoc。** 内部函数写单行英文注释即可。
### 标准模板

  

```javascript

/**

 * 一句话说清楚函数做什么（英文）

 *

 * @param {类型} 参数名 - 参数描述

 * @param {类型} [可选参数=默认值] - 描述

 * @returns {类型} 返回值描述

 * @example

 * const result = functionName('hello');

 * result;

 * // => 具体的返回值（必须真实可运行）

 */

```

### HashFunctions 示例

**同步函数（Murmur）**：

```javascript

/**

 * MurmurHash64A — 64-bit non-cryptographic hash.

 *

 * @param {string|ArrayBufferView|ArrayBuffer} data - Input to hash

 * @param {number} [seed=0] - Optional seed value

 * @returns {bigint} Unsigned 64-bit integer

 * @example

 * const result = mmh2('hello');

 * result;

 * // => 2191231550387646743n

 */

export function mmh2(data, seed = 0) { ... }

```

**异步函数（SHA）**：

```javascript

/**

 * SHA-1 (160-bit).

 *

 * @param {string|ArrayBufferView|ArrayBuffer} data - Input to hash

 * @returns {Promise<string>} 40-character uppercase hex string

 * @example

 * const result = await sha1('hello');

 * result;

 * // => 'AAF4C61DDCC5E8A2DABEDE0F3B482CD9AEA9434D'

 */

export async function sha1(data) { ... }

```

### `@example` 铁律

  

| 规则 | 说明 |

|---|---|

| 必须是真实可运行的代码 | 不能写伪代码或省略号 |

| `// =>` 后面写具体值 | 不能写"返回一个字符串"这种描述 |

| 异步函数加 `await` | `const result = await sha1('hello')` |

| bigint 末尾加 `n` | `// => 2191231550387646743n` |

| 变量名单独写一行 | 调用后再写 `result;` 再写 `// =>` |

### `@private` 标记

需求文档中**未提到**的内部方法，加 `@private`，不会出现在 API 文档中：

```javascript

/**

 * Read 8 bytes as little-endian uint64.

 * @private

 */

function readUint64LE(bytes, offset) { ... }

```

## 第4章 测试规范

### 文件分工

| 文件 | 内容 |

|---|---|

| `tests/main.test.js` | 测需求文档中提到的公开 API |

| `tests/unit.test.js` | 测内部工具函数、边界、异常 |

### 命名规范

- `describe` — 写被测对象名或场景名

- `it` — 以 `should` 开头，描述期望行为，**纯英文**

```javascript

describe('mmh2', () => {

    it('should return a bigint', () => {

        expect(typeof Murmur.mmh2('test')).toBe('bigint');

    });

});

```

### 必须覆盖的三类场景

  

| 场景 | 说明 | 示例 |

|---|---|---|

| **正常（Happy Path）** | 标准输入，期望正确输出 | `mmh2('hello')` 返回 bigint |

| **边界（Edge Case）** | 不同输入格式结果一致 | string、Uint8Array、ArrayBuffer 结果相同 |

| **异常（Error Case）** | 非法输入，期望报错 | `toUint8Array(null)` 抛出错误 |


### Jest 断言速查

  
```javascript

expect(x).toBe(y)           // 严格相等（数字、字符串、bigint）

expect(x).toEqual(y)        // 深相等（对象、数组）

expect(x).toBeNull()        // 是 null

expect(x).not.toBe(y)       // 不等于

expect(x).toBeInstanceOf(C) // 是某个类的实例

expect(fn).toThrow()        // 抛出异常

```

## 第5章 文档自动化

### 配置文件清单

**`jsdoc.json`** — 控制扫哪些文件生成 API 文档（只写需求中提到的文件）：


```json

{

    "source": {

        "include": ["src/main.js", "src/murmur.js", "src/sha.js"]

    },

    "opts": {

        "destination": "./docs/api-html/"

    }

}

```


> 新增或删除公开 API 时，同步更新 `include` 列表。`utils.js` 等内部文件不要加进去。

**`.babelrc`** — 让 Jest 能读懂 `import/export` 语法（固定写法，不用改）：


```json

{

    "presets": [["@babel/preset-env", { "modules": "commonjs" }]]

}

```

### 常用命令

  

| 命令 | 作用 |

|---|---|

| `npm test` | 跑所有测试 |

| `npm run test:coverage` | 测试 + 覆盖率报告 |

| `npm run docs:api` | 生成 API 文档（HTML） |

| `npm run docs:test` | 生成测试说明书（Markdown） |

| `npm run docs:all` | 同时生成两者 |

## 第6章 Code Review 清单


提交前必须逐项确认：

  

**代码**

- [ ] `src/main.js` 是唯一入口，不存在 `src/index.js`

- [ ] `main.js` 只包含 re-export，无算法逻辑

- [ ] 需求中提到的所有公开 API 有完整英文 JSDoc（`@param`、`@returns`、`@example`）

- [ ] `@example` 代码真实可运行，`// =>` 后是具体值

- [ ] 需求未提及的内部方法标记 `@private`

- [ ] 无 `console.log` / `console.warn`

- [ ] 无第三方运行时库引用

  

**测试**

- [ ] 测试描述全英文，`it` 以 `should` 开头

- [ ] 覆盖正常、边界、异常三类场景

- [ ] `npm test` 全部通过

  

**文档**

- [ ] `jsdoc.json` 的 `include` 只包含需求中的文件

- [ ] `npm run docs:all` 正常执行无报错
