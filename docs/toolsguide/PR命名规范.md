## 一、PR 标题规范

格式：`[类型] 简短描述（50字以内）`

表格

|类型|用途|示例|
|:--|:--|:--|
|`feat`|新功能|`[feat] 新增库存盘点页面`|
|`fix`|修复 Bug|`[fix] 修复日期选择器跨月显示错误`|
|`docs`|文档更新|`[docs] 补充 TimeObj API 使用说明`|
|`style`|代码格式（不影响逻辑）|`[style] 统一仓库模块缩进为2空格`|
|`refactor`|重构|`[refactor] 抽离表格渲染为独立组件`|
|`test`|测试相关|`[test] 补充 datetime 边界条件测试`|
|`chore`|构建/工具链|`[chore] 升级 jest 至 29.x`|

**示例标题：**

plain

复制

```plain
[feat] 仓库管理模块新增批量删除功能
[fix] 修复 #114 生产订单状态同步延迟问题
```

## 二、PR 描述模板

每次提 PR 时，把下面这段复制到描述框里填写：

Markdown

复制

代码预览

```markdown
## 变更摘要
<!-- 用1-2句话说明这个PR做了什么 -->
- 

## 关联需求
<!-- 关联的 Issue、需求文档或任务链接 -->
- Fixes #123
- 需求文档：[链接]

## 主要改动
<!-- 列出具体改了哪些文件/逻辑，方便 Reviewer 快速定位 -->
- [ ] 组件 `src/warehouse/InventoryTable.js`：新增批量操作栏
- [ ] 接口 `api/inventory.js`：新增 `batchDelete` 方法
- [ ] 测试 `__tests__/inventory.test.js`：覆盖批量删除场景

## 截图/GIF（如适用）
<!-- UI改动必填，有交互也建议贴GIF -->
![描述](链接)

## 测试情况
<!-- 说明你是怎么测的，Reviewer 可以复现 -->
- [ ] 本地 `npm test` 通过
- [ ] 手动测试场景：进入仓库页 → 选中3条数据 → 点击批量删除 → 确认弹窗 → 列表刷新

## 检查清单（提交前自查）
- [ ] 代码已按团队规范格式化（`npm run lint` 无报错）
- [ ] 新功能已补充测试用例
- [ ] 无 `console.log` / `debugger` 残留
- [ ] 接口变更已同步更新 API 文档或 JSDoc
- [ ] 无冲突，已基于最新 `main` 分支
```

## 三、Reviewer 评论规范

Review 时统一用以下标签开头，作者一眼知道怎么处理：

表格

|标签|含义|示例|
|:--|:--|:--|
|`【阻塞】`|必须修改，合并前必须解决|`【阻塞】这里缺少空值判断`|
|`【建议】`|最好改，但不强制|`【建议】变量名改为 activeTab 更清晰`|
|`【疑问】`|需要作者解释|`【疑问】这个魔法数字 86400 是什么意思？`|
|`【赞赏】`|写得不错，正向反馈|`【赞赏】这个抽离很干净 👍`|

---

## 四、如何落地到仓库

让你们仓库管理员在仓库根目录创建文件：

**`.github/pull_request_template.md`**

把上面的"PR 描述模板"内容复制进去保存。之后团队里任何人新建 PR，GitHub 会自动把这个模板填进描述框。

**标题：** `[fix] 修复 datetime.fromString 解析闰年2月29日异常`

**描述：**

Markdown

复制

代码预览

```markdown
## 变更摘要
修复 `TimeObj.fromString()` 在解析闰年2月29日时返回 `Invalid Date` 的问题，原因是正则未考虑闰年规则。

## 关联需求
- Fixes #88

## 主要改动
- [ ] `src/parser.js`：修正日期正则，增加闰年分支判断
- [ ] `__tests__/parser.test.js`：新增闰年/非闰年2月29日边界测试
- [ ] `docs/API.md`：补充 fromString 支持的日期格式说明

## 测试情况
- [x] 本地 `npm test` 通过（新增2个用例，全部通过）
- [x] 手动验证：`TimeObj.fromString('2024-02-29')` 正确返回日期对象

## 检查清单
- [x] `npm run lint` 无报错
- [x] 新增测试用例
- [x] 无调试代码残留
- [x] 已基于最新 main 分支
```
