# Module总述-Product

## Product产品

一个公司内部的asset管理，不管是tools，还是原料，还是要销售的产品，还是有库存的半成品，还是易耗品。都放在part里，根据不同用途，进行不同的配置

【Product Type】

产品用途选择完之后，会出现不同的topics，和默认不同的配置。

快捷选择：

1,2,3,4

Wizard选择：

1. 是产品/服务/内部工具固定资产
2. 产品-你出售吗（是否有销售topic）？你购买吗（是否有采购topic）？你在意/有能力长期维护确定数量吗（在expense账户还是asset.stock账户进行记账）？

销售：如果在这个公司，这种产品可以销售。那么就需要定销售产品名称，销售价格，销售单位，销售币种。

采购：如果在这个公司，这种产品需要采购。是否开启PO suggest（生成建立PO的todo）？是否auto issuePO自动生成PO单，生成批准PO的todo？从哪里采购，最小stock on hand多少。采购单位

仓库：配置仓位，在仓库的单位。跟踪Batch/Serial.

（其实这个财务在别的模块基本都要涉及）财务：如果是1，需要有账户管理他的原材料购买和消耗；客户账户和库存减少。如果是2，需要有expense账号管理他的购买和花销（一般不能销售，而是内部消耗）。如果是3，需要有账户管理他机器的购买和贬值消耗。如果是4，需要有账户记录收入。还有币种

问题：产品目录，分类？通过group起来，有专门创建group并排放产品层级的地方，这个类不是产品。group可以嵌套，但是part不可以，而且这个是个叶子很齐的树，不能长旁支，如果分类有5层，叶子不能在5层以下出现（区分生产bom的树）。

一个产品有好几个型号？有独特recipe的产品单独一个partnumbr，如果好几个型号，只是通过product group起来了。就像 牛仔裤（不可销售进货库存）-102蓝色牛仔裤（不可销售）-102蓝色M码/L码（可销售，进货，库存）。
